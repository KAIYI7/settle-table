# Architecture evidence collected for Phase 1

Accessed 2026-10-16. **Documentation evidence used in the completed [architecture assessment](architecture-decision.md); no framework selected.** These are documentation facts, not measured framework performance or an application configuration.

| Topic | Verified primary documentation | Implication to evaluate after experiments |
|---|---|---|
| Mobile capture | HTML file input `capture=environment` is a camera preference with limited cross-browser availability; desktop may show a file picker. getUserMedia requires secure context/permission. [Capture](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture), [camera](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) | Receipt photo UX is a device/browser concern independent of React versus Svelte. Must test actual target phones. |
| Offline web | Service workers/cache can serve previously provisioned assets; capabilities need feature detection. [PWA capabilities](https://web.dev/learn/pwa/capabilities), [caching](https://web.dev/learn/pwa/caching), [service worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API) | Installing a PWA alone does not make OCR assets, draft storage or queued writes offline-safe. |
| Vite | Default build produces static-hostable bundle; VITE_ values are bundled publicly. [Build](https://vite.dev/guide/build), [env](https://vite.dev/guide/env-and-mode) | Secret-backed Notion sync needs a separate runtime; local OCR does not inherently need full-stack framework. |
| Next.js | Runtime route handlers/actions can hold server work; static export supplies no live runtime and supports only build-time static GET output. [Static export](https://nextjs.org/docs/app/guides/static-exports), [BFF caveats](https://nextjs.org/docs/app/guides/backend-for-frontend), [security](https://nextjs.org/docs/app/guides/data-security) | One server deployment is possible, but static export alone cannot implement secret-backed live sync. Interactive OCR/editor is client work; SSR not proven necessary. |
| SvelteKit | Server-only modules/private env and deploy adapters; static versus server target choice is explicit. [Server-only](https://svelte.dev/docs/kit/server-only-modules), [adapter-node](https://svelte.dev/docs/kit/adapter-node), [adapter-static](https://svelte.dev/docs/kit/adapter-static) | A plausible full-stack alternative; no evidence that a receipt editor specifically requires React/Next. |
| Native/Flutter | Platform plugins declare supported platform implementations; native plugin availability does not imply a web implementation. [Developing packages/plugins](https://docs.flutter.dev/packages-and-plugins/developing-packages) | Device-native OCR may justify native build/release cost when strict device privacy or camera reliability is dominant. Actual ML Kit/Vision device evidence still required. |

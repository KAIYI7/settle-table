# Domain docs

Single-context convention. Read `GLOSSARY.md` before domain modeling; store durable accepted decisions in `docs/adr/` when they warrant an ADR. Research evidence stays under `research/`; Phase 1 requirements/domain reports distinguish proposals from confirmed choices. The orchestrator may accept technical decisions under `governance.md`, with evidence and rationale recorded. Product-policy preferences remain user decisions. Keep the glossary, research index and current specification consistent; never promote an experiment default silently into product behavior.
